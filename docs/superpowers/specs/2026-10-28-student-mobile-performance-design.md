# 학생 모바일 반응형·초기 렌더링 개선 설계

## 의도

휴대폰에서 필터·알림·토스트가 화면 밖으로 밀리거나 헤더와 겹치는 문제를 없애고, 인증 확인과 페이지 진입 시 반복 조회 때문에 첫 화면이 늦게 보이는 문제를 프론트엔드만으로 줄인다.

## 목표

- 모바일 viewport 안에서 필터, 알림 패널, 알림 토스트가 표시된다.
- 모바일 헤더의 두 줄 네비게이션과 액션 버튼이 좁은 화면에서 겹치지 않는다.
- 인증 확인 중에도 보호 화면을 빈 화면으로 막지 않고, 인증 실패가 확인되면 기존 리다이렉트를 유지한다.
- 동일 세션에서 반복되는 인증 GET 요청은 in-flight dedupe와 짧은 TTL 캐시를 사용한다.
- 알림 목록은 앱 초기 진입 때가 아니라 알림 패널을 열 때 조회한다.

## 제외 범위

- 백엔드 코드, API endpoint, HTTP method, payload, 인증 계약 변경
- 서버 쿠키 인증 도입 또는 React Query 같은 새 데이터 라이브러리 도입
- 데이터의 영구 저장이나 장기 캐시

## 접근 방식

1. 기존 FSD/App Router를 유지하고 shared API transport에 메모리 기반 인증 GET 캐시를 추가한다. mutation 성공과 세션 정리 시 캐시를 비운다.
2. AuthGate는 인증 확인 중 children을 렌더링하고, 실제 redirect가 결정된 경우에만 숨긴다. 이로써 초기 빈 화면을 제거한다.
3. 알림 목록의 초기 요청을 패널 열기 시점으로 지연한다.
4. 작은 트리거 버튼 기준의 모바일 `right-0` 배치를 viewport-safe 배치로 바꾸고, 메뉴 높이와 토스트 폭을 모바일 viewport에 맞춘다.

## 제약 및 판단

- localStorage 기반 인증이라 서버에서 보호 화면을 미리 판정할 수 없으므로, 인증 확인 중 잠깐의 보호 화면 노출 가능성은 허용한다. 실제 데이터 API는 기존 인증 검사를 계속 사용한다.
- 캐시는 탭 메모리에만 존재하고 기본 TTL은 30초로 둔다. 쓰기 요청 성공 시 전체 인증 GET 캐시를 무효화해 오래된 목록을 피한다.
- 일반 작업 PR의 base는 `develop`으로 유지한다.
