# 회원가입 약관 동의 흐름 설계

## 의도

회원가입 약관 동의 화면을 실제 동의 흐름에 맞게 정리한다. 사용자는 약관 내용을 확인한 뒤 모달의 `동의하기`를 눌러 해당 항목을 동의하고, 회원가입 화면에서 동의 상태가 자동으로 체크된 것을 확인할 수 있어야 한다. 화면은 모바일과 데스크톱에서 모두 읽기 쉽고 조작 가능해야 한다.

## 목표

- 중복된 하단 `닫기` 버튼을 제거하고 모달의 주 액션을 큰 `동의하기` 버튼으로 만든다.
- 모달의 `X`는 동의 없이 닫는 동작으로 유지한다.
- 약관별로 끝까지 확인한 뒤 `동의하기`를 누르면 해당 체크박스를 자동 체크하고 모달을 닫는다.
- 약관 행과 모달 액션을 반응형으로 배치한다.
- 모달의 포커스, Escape 닫기, 배경 스크롤, 설명 연결을 보완한다.
- 약관 전문의 명칭과 안내 문구를 실제 동작과 일치시킨다.

## 비목표

- 약관의 법률적 최종 검토나 운영 주체 정보의 확정
- 백엔드 DTO·DB·API 계약 변경이나 동의 이력 저장
- 로그인·비밀번호 재설정 UI의 재설계
- 마케팅 수신 동의처럼 현재 요구되지 않은 동의 항목 추가
- 별도의 약관 CMS 구축

## 제약

- 기존 Next.js App Router와 FSD 구조를 유지한다.
- 최신 `origin/main`에서 분기한 프론트 worktree에서 최소 범위만 수정한다.
- 백엔드 저장소와 기존 회원가입 API 계약은 변경하지 않는다.
- 기존의 인증 코드·비밀번호 가입 계약은 변경하지 않는다.

## 접근 방식

### 선택안 A — 약관별 모달 동의 (선택)

약관 목록은 반응형 행으로 유지하고, `자세히 보기`가 모달을 연다. 모달에는 `X`와 큰 `동의하기`만 제공한다. 본문 끝까지 확인하기 전에는 동의 버튼을 비활성화하고, 동의 시 약관별 체크박스를 자동 체크한다. 현재 사용자가 요구한 흐름을 가장 적은 범위로 반영한다.

### 선택안 B — 목록에서 바로 체크하고 모달은 정보만 제공

체크박스를 항상 활성화하고 모달은 단순 열람 용도로 둔다. 구현은 단순하지만 사용자가 지정한 “모달에서 동의하기” 흐름과 맞지 않고, 동의 액션이 모호해진다.

### 선택안 C — 약관을 별도 페이지로 분리

각 약관을 URL 페이지로 분리해 공유·검색은 쉽지만, 가입 흐름이 끊기고 동의 상태와 복귀 처리가 복잡해진다. 현재 범위에는 과하다.

## 구현 결정

- `SignupConsentDialog`는 `onAgree`를 받아 약관별 동의 결과를 부모 상태에 반영한다.
- `X` 또는 Escape는 동의하지 않고 닫는다.
- 동의 버튼은 `동의하기`로 표시하고, 약관 끝까지 확인된 경우에만 활성화한다.
- 약관 본문이 스크롤되지 않는 경우에도 열림 직후 동의 가능 상태를 계산한다.
- 회원가입 화면의 약관 행은 넓은 화면에서 체크박스·문구·자세히 보기를 한 행에 배치하고, 좁은 화면에서는 자세히 보기를 별도 줄의 충분한 터치 영역으로 배치한다.
- 개인정보 항목의 표기는 `개인정보 수집·이용 동의`로 통일한다.

## 검증 기준

- 약관을 끝까지 확인하기 전에는 `동의하기`를 누를 수 없다.
- `동의하기`를 누르면 해당 약관만 체크되고 모달이 닫힌다.
- `X`와 Escape로 닫으면 체크되지 않는다.
- 짧은 문서·큰 화면에서도 동의 버튼이 영원히 비활성화되지 않는다.
- 모바일에서 긴 라벨과 버튼이 겹치거나 화면 밖으로 밀리지 않는다.
- 회원가입 제출은 두 필수 동의가 모두 true일 때만 프론트에서 진행된다.
